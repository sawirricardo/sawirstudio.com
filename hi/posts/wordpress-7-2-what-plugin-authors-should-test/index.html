WordPress 7.2 आ रहा है 8 दिसंबर को: हम अपने प्लगइन्स में क्या टेस्ट कर रहे हैं

WordPress 7.2 की रिलीज़ 8 दिसंबर 2026 को तय है। पहला रिलीज़ कैंडिडेट 17 नवंबर को आना है, और तभी फ़ीचर लिस्ट फ़्रीज़ हो जाती है और Field Guide जारी होती है, यानी हर डेवलपर नोट की सूची। तब तक बीटा वर्शन पर टेस्ट करना यह पता लगाने का सबसे सस्ता तरीका है कि आपके प्लगइन में कोई समस्या तो नहीं है।

हम WordPress.org पर 12 फ़्री प्लगइन्स मेंटेन करते हैं, इसलिए यह हमारी अपनी चेकलिस्ट है। नीचे की कुछ बातें हमारे लिखते समय तक सिर्फ़ प्रस्ताव थीं; अंतिम जानकारी के लिए Field Guide देखें।

आज टेस्ट कैसे करें

  • टेस्ट साइट पर WP-CLI से: wp core update --version=7.2-beta4, या जो भी सबसे नया बीटा या RC हो।
  • WordPress Beta Tester प्लगइन, जिसमें “Bleeding edge” और “Beta/RC Only” चुना हो।
  • WordPress Playground, ताकि बिना कुछ इंस्टॉल किए ब्राउज़र में ही सब देख सकें।

लाइव साइट पर कभी नहीं। WP_DEBUG और WP_DEBUG_LOG चालू करें और डिप्रिकेशन नोटिस पर नज़र रखें; ज़्यादातर शुरुआती चेतावनियाँ वहीं दिखती हैं।

हम क्या जाँच रहे हैं

Application Passwords

7.2 में Application Passwords को और सख़्त किया गया है: लोकल और HTTPS सेटअप की बेहतर पहचान, नया पासवर्ड जोड़े जाने पर ईमेल, और डिफ़ॉल्ट रोल का ज़्यादा सुरक्षित इस्तेमाल। अगर आपका प्लगइन या आपके ग्राहकों के टूल इसी तरीके से REST API में ऑथेंटिकेट करते हैं, तो पूरा फ़्लो शुरू से आख़िर तक चलाकर देखें।

Secrets API

क्रेडेंशियल एन्क्रिप्ट करके रखने का कोर का अपना तरीका, ताकि प्लगइन्स API कुंजियाँ सादे ऑप्शन के रूप में न रखें। इसे 7.2 के लिए प्रस्तावित किया गया था, और एडमिन स्क्रीन 7.3 तक टल गई है। अगर आपका प्लगइन API कुंजियाँ स्टोर करता है, तो Field Guide में इस पर नज़र रखें: रिलीज़ होने के बाद कुंजियाँ रखने की सही जगह यही होगी। हमारा कोई भी फ़्री प्लगइन आज थर्ड-पार्टी कुंजियाँ स्टोर नहीं करता, इसलिए हमारे लिए यह क्लाइंट के काम से जुड़ा मामला है।

Sudo mode

योजना यह है: बहुत ऊँचे अधिकार वाले काम करने से पहले लॉग-इन यूज़र से दोबारा पासवर्ड की पुष्टि माँगी जाए। अगर आपका प्लगइन अपनी स्क्रीन से या AJAX के ज़रिए ऐसे काम करता है, तो टेस्ट करें कि बीच में कोर दोबारा पुष्टि माँगे तो क्या होता है।

Interactivity API राउटर

क्लाइंट-साइड नेविगेशन पर नज़र रखने के लिए एक नया राउटर आया है, जो डिप्रिकेट हो चुकी जोड़ी state.navigation.hasStarted और hasFinished की जगह लेता है। भरोसेमंद मार्कअप रेंडर करने के लिए एक data-wp-html डायरेक्टिव भी है।

एडमिन आइकन और नोटिस

एडमिन बार और मेन्यू में Dashicons की जगह SVG आइकन आ रहे हैं, और एडमिन नोटिस के लिए स्क्रीन रीडर की घोषणाएँ बेहतर हुई हैं। अगर आपका प्लगइन अपने मेन्यू आइकन की स्टाइलिंग करता है या एडमिन CSS में Dashicon क्लास को टारगेट करता है, तो उसे बीटा में देख लें।

DataViews और साइट एडिटर

प्लगइन्स साइट एडिटर में अपनी स्क्रीन रजिस्टर कर सकते हैं और सर्वर से DataViews के फ़ील्ड और लेआउट नियंत्रित कर सकते हैं। इससे कुछ टूटता नहीं है, लेकिन अगर आपके प्लगइन में कोई लिस्ट स्क्रीन है, तो यह जानना फ़ायदेमंद है कि चीज़ें किस दिशा में जा रही हैं।

टेस्टिंग के बाद

अपनी readme में “Tested up to” तभी बढ़ाएँ जब आपने सच में टेस्ट कर लिया हो, उससे पहले नहीं। जब कोई प्लगइन पिछले मेजर रिलीज़ के साथ टेस्ट नहीं किया गया होता, तो WordPress.org यूज़र को चेतावनी दिखाता है, और उस चेतावनी से इंस्टॉल घटते हैं। हमारे प्लगइन्स में अभी “Tested up to: 7.1” लिखा है; RC पर पास होने के बाद हम उसे 7.2 कर देंगे।

नई डिफ़ॉल्ट थीम Ipsum भी इसके साथ आ रही है। अगर आपका प्लगइन फ़्रंट एंड पर कुछ भी दिखाता है, तो उसे वहाँ जाँच लें; नई साइटें ऐसी ही दिखेंगी।

अगर आपके पास कोई प्लगइन है जिसे 7.2 के लिए अपडेट करना है, या कोई कस्टम प्लगइन जिसे अब कोई मेंटेन नहीं करता, तो हम उसे देख सकते हैं।

यह भी पढ़ें: Abilities API से अपने WordPress प्लगइन को AI एजेंट्स के लिए इस्तेमाल योग्य बनाएँ, या इंडोनेशिया के बिज़नेस के लिए WooCommerce या Shopify?।

क्या इस पोस्ट से आपने कुछ नया सीखा?

मुझे आपका ईमेल पता चाहिए, ताकि जब भी कोई नई पोस्ट प्रकाशित हो, मैं आपको ऐसी ही और पोस्ट भेज सकूँ।

    मैं आपको स्पैम नहीं भेजूँगा। आप कभी भी सदस्यता छोड़ सकते हैं।
