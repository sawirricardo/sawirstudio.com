# sawirstudio.com

A static site built with Go and [templ](https://templ.guide), served by one Go binary on our own
server (ricardosawir1) behind Cloudflare. The binary also takes the contact form's inquiries
into Postgres (pgx, sqlc, dbmate migrations).

```
content/<path>.html        Source of each English page: front matter, then the HTML inside <main>
                           (content/home.html is /, content/projects/rindraw.html is /projects/rindraw/)
content/projects.yaml      The project list: cards, categories, search text, order
content/site.yaml          Site settings (where the contact form posts)
internal/site/             Builder: layout, header, footer, cards, "More projects", CTA (*.templ)
cmd/build/                 go run ./cmd/build: writes the English pages from content/
internal/server/           The web server: static files, Markdown for agents, redirects, POST /api/inquiries
cmd/server/                The server binary (the built site is embedded into it by make dist)
db/migrations/             dbmate migrations; db/queries/ the SQL sqlc turns into internal/db/
deploy/sawirstudio.service systemd unit on ricardosawir1

index.html, */index.html   Built pages (generated, committed: don't edit, edit content/)
<lang>/                    Translations (generated by scripts/i18n.py)
**/index.md, llms.txt      Markdown copies of the pages for AI agents (generated)
assets/                    CSS, JS, images, share pictures (assets/og/; assets/og/cards/ is drawn by the builder)
internal/ogcard/           Draws the share cards (Bricolage Grotesque built in, OFL)
sitemap.xml, robots.txt, _redirects
scripts/i18n.py            Translations
scripts/markdown_pages.py  Markdown copies and llms.txt
scripts/press_kit.py       Press kit logos in assets/press/
```

Needs Go, [sqlc](https://sqlc.dev) (only to change queries) and uv. templ is pinned in `go.mod`
(`go tool templ`).

## Run locally

```bash
make serve
```

Open http://127.0.0.1:8098. Without a database the contact API answers 503; for one, run Postgres and
`make migrate serve DATABASE_URL=postgres://...`.

## Editing pages

Edit the page's file in `content/`, then rebuild the English pages, the translations and the Markdown copies:

```bash
make site
```

`make site` doesn't call the translator. When you've added or changed text, translate it first with
`uv run scripts/i18n.py` (it sends only the new text to the `claude` CLI), then run `make site`.

A content file starts with front matter:

```yaml
---
title: Rindraw | Sawir Studio
description: A drawing app where every stroke stays editable.
og_type: website            # article for blog posts
og_image: /assets/og/rindraw.jpg   # leave out to use the drawn card in assets/og/cards/
twitter_card: summary       # default summary_large_image
convertkit: true            # the newsletter form (blog posts)
related: true               # the "More projects" row (project pages)
cta: false                  # leave out the "How can we help you?" box
ld: |                       # JSON-LD, as is
  { ... }
---
```

The header, footer, `hreflang` links, language list and share image tags come from `internal/site/`.
Two placeholders in a page's HTML are filled in by the builder: `<!-- @project-cards -->` (the project
list) and `<!-- @inquiry-form -->` (the contact form).

## Adding content

Add a file under `content/projects/` or `content/posts/` (copy an existing one), link it from the
blog list or the home page if it belongs there, and add its URL to `sitemap.xml`.

For a project, add it to `content/projects.yaml` where it should appear in the list, with its
categories (1 Design, 2 Website, 3 Application) and lowercase search text. The list's cards and the
"More projects" row on every project page come from that file.

The picture on a project's card grows into the picture at the top of its page (a view transition). Give the
page's top picture (`.project-hero`, or `.app-icon` for our own apps) `style="view-transition-name: media-<slug>"`,
and the home page's picture too if the project is featured there; the card gets it from the builder.

`make pages` also draws each page's share card (the picture shown when the link is shared) in
`assets/og/cards/`: the page's title on the site's card design, with a Blog or Services label where it
fits. Project pages keep their own picture in `assets/og/` (`og_image`). Cards no page uses are removed.

`make site` also rebuilds the Markdown copies and `llms.txt`. The server sends a page's `index.md` to
requests with `Accept: text/markdown` (agents), and adds `Link` headers pointing to it, `llms.txt` and the sitemap. Check with https://isitagentready.com/sawirstudio.com.

## Translations

Every page also exists in Simplified Chinese (`/zh-hans/`), Traditional Chinese (`/zh-hant/`), Japanese (`/ja/`), German (`/de/`), French (`/fr/`), Russian (`/ru/`), Hindi (`/hi/`), Dutch (`/nl/`), Italian (`/it/`), and the right-to-left Hebrew (`/he/`) and Arabic (`/ar/`), built from
the built English pages by `scripts/i18n.py`. Don't edit the files under those folders; edit `content/` and rebuild:

```bash
make pages
uv run scripts/i18n.py           # translates new or changed text with the claude CLI, then rebuilds
make markdown
```

Translations are kept in `i18n/<lang>.json` (English HTML → translation), so only changed text is sent for
translation. To fix a translation, edit it there and run `make translations`. The script also adds the
`hreflang` links and the footer language list to the translated pages, and the translated URLs to `sitemap.xml`.
To add a language, add it to `LANGS` in the script and to `Langs` in `internal/site/langs.go`.

## Contact form

The form is `internal/site/inquiry.templ`. `inquiry_api` in `content/site.yaml` says where it posts:

- empty (for now): the Google Form "SawirStudio inquiries"
  (edit: https://docs.google.com/forms/d/1J5pXtNHc4mB3SXJNIkbOJRf6OHx-ToGfELj3XZoaHl8/edit). Each field's
  `name` is that question's `entry.<id>`; get new IDs with
  `gog forms raw 1J5pXtNHc4mB3SXJNIkbOJRf6OHx-ToGfELj3XZoaHl8`, and read responses with
  `gog forms responses list 1J5pXtNHc4mB3SXJNIkbOJRf6OHx-ToGfELj3XZoaHl8`.
- `/api/inquiries` (now): our server, which checks the fields, drops bots (a hidden `website` field), allows
  5 inquiries per IP address per 10 minutes, and stores them in the `inquiries` table. Read them with
  `ssh ricardosawir1 "sudo -u postgres psql sawirstudio -c 'select created_at, name, email, company, needs, message from inquiries order by created_at desc limit 20'"`.

Each new inquiry is also emailed to `NOTIFY_TO`, with Reply-To set to the inquirer, so replying answers
them. It goes out through Cloudflare's email REST API from `inquiries@notify.sawirstudio.com`: Email
Routing is on for the `notify` subdomain only (the apex's mail stays with Lark), and a routing domain may
send to the account's verified destination addresses. `/etc/sawirstudio/env` on the server sets
`CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_EMAIL_TOKEN` (an account API token with Email Sending permission),
`NOTIFY_FROM` and `NOTIFY_TO`; without them the server stores inquiries and logs that emails are off.
`notified_at` records when an email went out; at start the server sends any from the last week that didn't.

After changing it, run `make site` (every language's contact page changes) and deploy.

## Database

Migrations are in `db/migrations/` (dbmate format). The server applies new ones when it starts
(or run `sawirstudio-server migrate`), so a deploy is only the binary. To add one:

```bash
dbmate --migrations-dir db/migrations new add_something   # then write the SQL
make migrate generate                                     # apply locally, regenerate sqlc
```

Queries are in `db/queries/`; `sqlc generate` turns them into `internal/db/`. For the API tests, point
`TEST_DATABASE_URL` at a migrated database: `TEST_DATABASE_URL=postgres://... go test ./...`.

## Deploy

```bash
make deploy
```

This builds one Linux binary with the site inside it (`make dist` copies everything but what `.assetsignore`
lists into `.dist/site`, which `embed.go` embeds), copies it to `ricardosawir1:/usr/local/bin/sawirstudio-server`
with `deploy/sawirstudio.service`, restarts the service and checks `/healthz`. It stops if `content/` has
changes the built pages don't have yet (run `make site`).

On ricardosawir1 the server listens on `127.0.0.1:8098`. The tunnel `ricardosawir1` (cloudflared, its routes set
in Cloudflare Zero Trust) sends sawirstudio.com and www.sawirstudio.com there; the server redirects www to the
apex. `/etc/sawirstudio/env` (root only) sets `DATABASE_URL`, for the `sawirstudio` database and role.

Cloudflare sits in front. Nothing is fingerprinted, so every file is sent with
`Cache-Control: public, max-age=0, must-revalidate` and an ETag: Cloudflare and browsers recheck it each
time (a 304 when unchanged), and a deploy shows up at once. Markdown answers are `private, no-store`, since
Cloudflare's cache doesn't vary on `Accept`. `make deploy` also purges sawirstudio.com from Cloudflare's
cache with the Cloudflare CLI (`cf`).
