# ما الذي تطلّبه جعل مواقعنا جاهزة للوكلاء الذكيين

لم تعد كل زيارات المواقع من أشخاص. فجزء متزايد منها وكلاء ذكاء اصطناعي يقرؤون الصفحات للإجابة عن سؤال أحدهم، أو يحاولون استخدام منتج نيابةً عنه. وخلال هذا الأسبوع راجعنا هذا الموقع ومواقع منتجاتنا، ومنها [SawirPost](https://sawirstudio.com/ar/projects/sawirpost/) و[Sawirly](https://sawirstudio.com/ar/projects/sawirly/) و[Rindraw](https://sawirstudio.com/ar/projects/rindraw/) و[Math Daily](https://sawirstudio.com/ar/projects/math-daily/) وغيرها، لنجعل قراءتها واستخدامها أسهل على الوكلاء.

اعتمدنا موقع [isitagentready.com](https://isitagentready.com) قائمةً مرجعية. فهو يقيّم الموقع على مستويات، وفيما يلي ما تطلّبته كل خطوة.

## نسخ Markdown لكل صفحة

يضطر الوكيل الذي يقرأ HTML إلى المرور عبر القوائم والسكربتات والتذييلات ليصل إلى بضع فقرات. لذلك صار لكل صفحة في هذا الموقع نسخة Markdown بجانبها، في المسار `index.md`، تحتوي على المحتوى الرئيسي للصفحة فقط. ويبني سكربت صغير هذه النسخ من HTML، فلا تختلف عن الصفحة الأصلية أبدًا.

ويصل الوكلاء إليها بطريقتين: بإضافة `index.md` إلى الرابط، أو بطلب `Accept: text/markdown`. يفحص Cloudflare Worker صغير أمام الملفات الثابتة هذا الترويسة ويقدّم نسخة Markdown، مع عدد تقريبي للرموز (tokens) في ترويسة `x-markdown-tokens`. أما المتصفحات فتحصل على الصفحة العادية كما هي.

```
curl -H "Accept: text/markdown" https://sawirstudio.com/shopify/
```

## ترويسات Link

تذكر كل صفحة HTML الآن مكان نسخة Markdown الخاصة بها، في ترويسة HTTP من نوع `Link` مع `rel="alternate"`. كما تشير الصفحة الرئيسية إلى `llms.txt` وخريطة الموقع. وبذلك يعثر الوكيل على كل شيء من طلب واحد دون تخمين الروابط.

## llms.txt

`llms.txt` فهرس نصي بسيط للموقع موجّه إلى نماذج اللغة: ملخص في سطر واحد وقائمة بكل الصفحات مع وصف كل منها، وتشير إلى نسخ Markdown. ويُنشأ ملفنا من خريطة الموقع بالسكربت نفسه.

## Content Signals

يحدد `robots.txt` من يحق له الزحف، لكنه لا يحدد ما يجوز له فعله بما يقرؤه. وهنا يأتي دور [Content Signals](https://contentsignals.org/). وفي موقعنا هو سطر واحد يسمح بالاستخدامات الثلاثة، لأننا نريد أن يُعثر علينا وأن يُقتبس منا:

```
Content-Signal: ai-train=yes, search=yes, ai-input=yes
```

هذه الخطوات الثلاث أوصلت كل المواقع إلى المستوى 3.

## كتالوج API وAgent Skills

لدى SawirPost وSawirly واجهات API، فذهبتا أبعد من ذلك. تنشر كل منهما كتالوج API في `/.well-known/api-catalog` (RFC 9727): وهو مستند JSON صغير يشير إلى وصف OpenAPI والوثائق. وبذلك يستطيع الوكيل الذي يصل إلى الموقع أن يجد واجهة API دون قراءة أي صفحة.

وتنشران كذلك Agent Skills، وهي تعليمات قصيرة للوكلاء توضح كيفية إنجاز المهام الشائعة في المنتج. وبذلك وصلتا إلى المستوى 4.

## أين توقفنا

يتطلب المستوى 5 أن يتمكن الوكلاء من التسجيل والمصادقة بأنفسهم، عبر مسار تسجيل الوكلاء في OAuth. أما صفحة تشرح كيفية التسجيل بالبريد الإلكتروني وكلمة المرور فلا تُحتسب. وهذه ميزة حقيقية تحتاج إلى بناء، وتثير أسئلة أمنية جدّية، لذلك نفكر فيها بروية بدل التسرع.

## هل كان الأمر يستحق؟

في موقع ثابت، استغرق معظم هذا العمل بعد ظهر يوم واحد: سكربت واحد، وWorker صغير واحد، وسطر في `robots.txt`. ولم يتغير شيء بالنسبة لمن يزورون الموقع من البشر. ونتوقع أن يزداد عدد الأسئلة التي يجيب عنها الوكلاء بقراءة مواقع مثل موقعنا، وصفحة Markdown نظيفة هي أسهل طريقة ليُقتبس منك بدقة.
